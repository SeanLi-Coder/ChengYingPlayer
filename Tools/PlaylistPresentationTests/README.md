# Native playlist presentation tests

Run `bash Tools/PlaylistPresentationTests/run.sh` on macOS with Xcode command-line tools. Set `CHENGYING_CAPTURE_DIR` to export native English and Simplified Chinese screenshots in light and dark appearances at 240, 270, 360, and 800 points.

The suite compiles the production sort controls, tag renderer, metadata model, and shared styling without stubs. It exercises the real targets and actions, sort-key/direction/manual state, refresh disabling, full tooltip/accessibility names, cleared tags, actual Finder-color pixels, and native layout bounds. Production sources are also typechecked for Intel macOS 10.15 compatibility.

The additional integration executable mechanically extracts the current controller's metadata/sort methods and complete cell classes, rather than copying their implementations. Only controller access control is relaxed in a temporary test copy. A small `PlayerCore` boundary double represents mpv snapshots and reorder calls; Foundation metadata reads, queues, generation handling, completion closures, and AppKit views remain real. These sources are also typechecked for Intel macOS 10.15. Tests cover finished-operation lifetime, obsolete-generation rejection, changed entry IDs, duplicate paths, superseded sort requests, stop/inactive cancellation, refresh without reordering, deinitialization, empty lists, toolbar insertion, and cell token/reset behavior.

The action executable also extracts the production context-menu, copy/paste, and subtitle-popover methods. It verifies that open menus retain their original file identities across live playlist changes, including changes while a trash error alert is shown. Playback, filesystem deletion, external applications, and modal file selection are boundary doubles: no real files are trashed and Finder is never opened. The actual secure pasteboard archive, malformed URL parsing, subtitle filtering, and out-of-range popover handling remain real. The fixtures cover duplicate paths, failed or unavailable snapshots, stopped players, removed/reopened targets, and delayed subtitle-panel completions.

On command-line-tools hosts without `ibtool`, `XIBLayout.swift` reconstructs the cell's actual checked-in XIB outlets and constraints and then runs production `awakeFromNib`. These layout tests render real production cell/tag/progress views. They intentionally do not claim to validate NSNib decoding, Cocoa bindings, asset lookup, or pixel-identical Interface Builder font/bezel settings; a full app build remains required. Captures named `playlist-cell-*` show these production cells. The suite does not emulate real mpv event timing or Finder activation delivery; playback and metadata policies have separate tests.
