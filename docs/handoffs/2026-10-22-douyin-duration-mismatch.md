## 实站证据（2026-10-22）

匿名单作品测试返回登录要求。授权后的主页定点解析首次未取得所需站点脚本，
单作品解析成功；网页详情声明视频时长 `50804 ms`、尺寸 `1080×1920`。
没有把匿名失败或主页入口失败当成账号失效，也未切换其他 Chrome 配置。

当前源码的完整媒体检查复现相同错误。响应不是下载到 10 秒就断开：
下列候选均已完整接收并通过原有长度与前缀一致性检查后再执行本地 FFprobe：

| 候选实测 | 字节数 | 视频轨时长 |
| --- | ---: | ---: |
| H.264，720×1280 | 2,976,476 | 10.033333 秒 |
| HEVC，576×1024 | 1,005,809 | 10.033333 秒 |
| 官方 default 入口 HEVC，1080×1920 | 17,047,217 | 10.033333 秒 |

另一次只保留脱敏数值的诊断，对最高档完整文件枚举所有 packet：

- 视频轨：301 个 packet，PTS 从 `0` 到结束时间 `10.033333` 秒。
- 音频轨：2190 个 packet，PTS 从 `-0.047891` 到结束时间约 `50.803991` 秒。
- 容器时长约 `50.803991` 秒，音频轨时长相同；这不能证明有 50 秒视频画面。
- 首个 H.264 候选亦为 10.033333 秒视频与约 50.803810 秒音频。

因此不能通过单纯改用 `format.duration`、取最长轨道、放宽容差或补帧来宣称
找到了完整 50.8 秒画面。也尚未证明站点存在另一个可取得的 50.8 秒视频源。
仅测试正常允许的站点入口，不绕过登录、访问限制、可信域名或 HTTPS 校验。

## 另行确认的解析缺陷与本地修补

独立合成测试发现：小于 256 KiB 的完整 fragmented MP4，经不可定位的 pipe 输入
FFprobe 也可能只报告首个 fragment 的时长。50.8 秒合成文件可精确误报为 10.033 秒。
旧代码因已取得全部字节而跳过本地 seekable 复核，是可独立复现的缺陷；
但用户当前三个实际候选更大，完整本地文件与 packet 复核仍然只有 10 秒画面，
不能把这个小文件修补当成本次作品已经恢复。

本地修补对时长冲突始终进行 seekable 复核。只有 HTTP 200 或 206 的长度、
Range 起止与总长证明当前缓冲包含完整对象时，才将相同字节写入独占临时文件，
不额外请求；未知或不完整长度仍走原有完整下载。严格容差、身份、最高档/default、
尺寸、内容指纹、取消、临时文件清理与原有复用边界均保留。

新增 helper 合成测试；只精确修正上游一个 mock 测试对 pipe 的错误假设，
仍要求不重复联网、真正短视频拒绝。第三个上游测试补丁已明确记入清单和验证器，
原始上游 SHA 与许可不变。这个独立修补本身不修改队列策略。

## 用户确认后的原样文件策略

原生 host 显式启用 `allow_douyin_unequal_tracks`，Standalone 默认和 Live Photo 保持严格。
仅完整可定位文件、准确字节数、正数有限时长都已验证，且较长音频与容器均吻合网页
声明时，才接受较短的视频轨。原视频时长仍是指纹，不取最长轨替换；四个独立数值
随候选进入缓存键与最终保存复核，最终测量差异不得超过 1 毫秒。缺失、矛盾、截断、
前缀单独证据不能放行。身份、最高画质及 mandatory default、安全 URL 等门禁不变。

成功明细显示原样文件的视频／音频时长与未转码／未补帧提示，重启保留、重新尝试清除
过期证据。仅白名单有限数值可持久化／输出，不接纳网站任意文案。

再次使用获准的 Profile 1 仅测试该作品，完整生产下载路径通过：

- FFmpeg 对完整保存文件全部音视频解码通过；结果携带四值提示信息。
- 输出、探测候选和分片的独占临时目录已清理并检查不存在；没有改用户下载历史。
