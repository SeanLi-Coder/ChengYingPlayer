# Movist：播放内核、界面与交互参考

日期：2026-10-12（Asia/Shanghai）。源码基线：`d7cc6fea`；研究分支：
`codex/movist-core-reference`。本文件记录研究、独立实现与验收边界，不是整体换核声明。

## 用户确定的方向

Movist Pro 是播放体验的主要参考，范围同时包括播放内核、界面和操作体验。
不能把需求缩减为皮肤调整，也不预先把“永远保留原播放内核”当作限制。
是否升级现有依赖、增加原生后端或替换呈现路径，由同素材、同设备、同画质的测试决定。

已有用户规则优先于参考软件默认行为：新视频音量为零并同步滑块；全局循环模式记忆；
`C/X` 每次调整 0.1 倍；`[/]` 设置 A/B 且 seek、变速、逐帧不逃出区间；
画面缩放与平移、永久旋转快捷键、剪辑自动预览、纯净图片窗口、目录多选和安全文件操作保留。
不重置显式 HDR 偏好、系统权限、下载身份、模型或用户数据，保持已有更新身份与增量更新。

## 证据与边界

### 第一方公开行为

- [官方功能说明](https://movistprime.com/en/)：提供 FFmpeg / QuickTime 解码选择、
  HDR 到 SDR 映射、按需显示控件和进度条缩略图。这是产品功能描述，不是全部内部架构。
- [官方 FAQ](https://movistprime.com/en/faqs.html)：硬件、强制硬件及软件解码可选，
  强制模式并非对所有文件安全；播放中可以切换。10-bit 能力识别也可能失败。
- [官方更新记录](https://movistprime.com/en/changelog.html)：2.13.0 宣布 M3/M4 的 AV1 硬解；
  2.15.4 将默认“renderer”改为 VideoToolbox 以处理 macOS 15 MacBook Pro 卡顿。
  该术语不能证明零拷贝、Metal、具体线程或同步算法。
- 同一更新记录记载过 A/B 越界、seek 首尾不可达、HEVC 颜色和音画同步修复。
  参考软件也有缺陷，不能照搬其所有行为；Dolby Vision 播放支持和 tone mapping 的
  profile 限制必须分别核实，不能概括为所有动态 HDR 均完整支持。

### 实施前 ChengYing 的可核实差异（基线 d7cc6fea）

播放链路为 `PlayerCore → MPVController → libmpv → FFmpeg/VideoToolbox → OpenGL/CAOpenGLLayer`。
锁定的播放依赖是 mpv 0.38.0 / FFmpeg 7.1.5，与剪辑和下载工具使用的 FFmpeg CLI 独立。
升级工具用的 FFmpeg 不能等同于升级播放器内核。

| 领域 | 当前证据 | 待验证的改进方向 |
| --- | --- | --- |
| AV1 | `MPVController.adjustCodecWhiteList` 即使检测到硬件支持也移除 AV1；当前播放 FFmpeg 缺少对应 VideoToolbox 路径 | 验证支持 AV1 硬解的依赖组合，不能只删保护条件 |
| 开播 | `HardwareDecodeCapabilities` 首次取值可能等待后台能力检测 | 测冷、热开播到实际首帧的延迟，不能只从 `wait()` 推断瓶颈 |
| seek | `.auto` 使用一次 seek 的 50 ms 判断；事件在主线程处理，耗时含调度等待 | 测连续拖动、长 GOP 和长文件的实际目标帧；评估过时请求合并 |
| 呈现 | libmpv OpenGL render API 与 `ViewLayer` | 比较现有路径、升级依赖和原生呈现候选；不把 API 名称当作性能结果 |
| 音画同步 | 变速及音调修正已有；现有 soak 使用 `ao=null` | 增加真实 CoreAudio 输出、变速、seek 和设备切换后的同步验证 |
| 长时播放 | 真实 4K soak 默认 180 秒，使用六秒循环素材；最低吞吐门槛只是存活检查 | 补帧间隔、掉帧、长文件、整 App 和多小时观测 |
| HDR | 已有像素、ICC、HDR 状态恢复检查 | 补 M4 Max 实屏 EDR、外接 SDR 屏切换和硬解组合；普通截图不是 HDR 验收 |
| 关闭 | 已有生产渲染锁、ASan、窗口关闭重开回归 | 保留严格门槛，新增后端也要覆盖快速换片、关闭、取消和多窗口 |

这些是能力差异或测量缺口，不是已经证明的用户故障根因。
现有真实回归不能被删掉；新增性能基准也不能通过静默降分辨率、减少画质或关闭字幕获得优势。

## 分阶段实施与通过条件

1. **建立对照基线。** 在授权的正常 Movist UI 和隔离 ChengYing 测试构建中，使用相同合成或
   可再分发素材、输出尺寸、屏幕刷新率和电源条件。分别记录冷/热首帧 P50/P95、seek 到实际帧
   的延迟与误差、帧间隔分布、掉帧、真实硬解状态、内存和关闭耗时。先做短测试，再做长时测试。
   性能测量与侵入式诊断分开；没有记录的指标标为未测，不从主观观感编造倍数。
2. **Apple Silicon 解码候选。** 独立构建支持 AV1 VideoToolbox 的播放依赖组合；明确记录来源、
   SHA、ABI 和补丁链。M2 没有 AV1 硬解不能冒充 M4 验收；M4 Max 需验证实际选中的解码器、
   画面、软件回退及切换状态恢复，保留 H.264/HEVC/VP9/ProRes 的既有兼容保护。
3. **原生呈现/后端候选。** 评估 AVFoundation 原生播放路径，或 FFmpeg/VideoToolbox 解码加
   原生呈现的独立实现。需明确字幕、滤镜、音轨、seek、时间基准和关闭资源所有权；不预先承诺
   AVPlayer/Metal 一定优于 libmpv，也不为了“参考 Movist”强行一次性全部重写。
   候选必须保留兼容路径，失败时明确报告，不能静默丢 HDR、字幕、音轨或 A/B 状态。
4. **界面与操作同步调整。** 以视频画面为主、底部轻量进度区、右上角列表/信息/设置小入口、
   靠近显示和静止隐藏、悬停预览。隐藏控件只是呈现状态，不能关闭工具或停止剪辑预览。
   菜单、滑块和实际播放状态一致；保留键盘输入焦点、多选、列表高度记忆与窄窗可用性。
5. **选择与发布。** 以测量结果选择后端或改动，不用自动回退掩盖失败。先过原回归和新增
   场景，再按 `AGENTS.md` 完整构建、签名、增量更新与公开交付门禁发布，不发布仅改皮肤却
   宣称已换内核的版本。不删除历史开源版权、来源和许可证。

## 第一批实验实现（v0.2.80 / build 91，未发布）

以下代码和实验结果保留于 `codex/movist-core-reference`（`e372bbd6`）。AV1 部分未通过
硬件验收，不在 v0.2.81 稳定候选中；后者只保留下列 seek、底栏与独立测试宿主修补。

1. **AV1 解码能力。** 保持 mpv 0.38.0 / FFmpeg 7.1.5 ABI，将 FFmpeg 官方
   `f9c5c5358cfef3847674c6f3b3ded9611ebc5647` 的 AV1 VideoToolbox 运行时改动回移。
   不套用开发分支版本号变更；补丁、修改前后源码、新增文件、构建记录和源发布包均有独立校验。
   AV1 只有在设备支持且已加载库确实提供 VideoToolbox 配置时才保留在硬解白名单，旧设备仍可软件解码。
   现有五个 mpv 色彩/渲染补丁不变，不以删除保护条件冒充内核支持。
2. **自动 seek 正确性。** 首次探测始终精确定位，新文件重置上一个文件的测量策略。
   SEEK/RESTART 时间在事件读取时记录；主线程排队时间不再被误计入间隔。
   单次样本由 token、媒体代次和五秒有效期约束；新 seek、换片、停止、重入及无效时间取消旧测量。
   无法可靠归属的样本保守保留 exact，不全局节流或重排用户定位命令，不修改 A/B 边界与暂停重绘。
3. **底栏交互。** 原播放/前后跳转组在有空间时居中，音量留在右侧。
   居中是低优先级布局偏好，窄窗时允许左移，不撑大窗口、不挤掉音量、不创建第二套播放按钮。
   自动隐藏、快捷键、鼠标焦点和现有菜单状态同步保持原实现。

### 本机实验候选验证（不等同于 v0.2.81 验收）

- 新播放库在隔离目录从固定源码编译完成；9 个 ARM64 dylib 签名、哈希和 69 个生产初始化参数检查通过。
- 实际库 AV1 8/10-bit 合成素材各解码 24 帧，软件模式与请求 VideoToolbox 的精确 seek、EOF、销毁通过。

- 新候选 SDR/PQ/HLG 中性阶梯像素、ICC 所有权和切换像素检查通过；不等同于 EDR 实屏验收。

  15 次 seek、9 次变速，硬解实际选中；177 次内存采样 RSS 首末差为 -3.2 MiB。
  这是三分钟合成循环素材检查，不是多小时影片或 Movist 性能对比。
- 居中底栏 667 项、集成 638 项、可见性生命周期 174 项、交互 40 项检查通过，另目视核查 640/285 点宽度。

  证明可复现原缺陷。事件测试使用 `vo=null`，不宣称画面呈现或音画同步性能。
- 4K 关闭回归的初始基线出现失败，已保留 fail/pass/fail 固定组，而非只记录一次成功。
  增加只读诊断后观察到窗口不在 active Space、被遮挡，mpv 事件和渲染队列仍有进展。
  测试宿主补齐 `finishLaunching`、正常窗口激活和 AppKit 事件分发后，新候选预定三组各 30 次
  关闭重开全部通过；独立普通无诊断硬解门禁也通过，观察到 179 张真实画面和 VideoToolbox。
  增加 16 项原生事件队列/可见性正反对照；不改生产渲染器、不放宽帧数或时限。
  固定组记录位于本地 `build/movist-window-lifecycle-candidate-fixed-2026-10-12`，所有测试 App 清理完成。
