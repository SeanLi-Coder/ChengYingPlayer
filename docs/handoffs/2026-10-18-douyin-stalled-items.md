## 已确认并修补的缺陷

### 图片头分段到达被过早判定失败

Douyin 传输使用 Requests 的 `read1`，首块不保证有完整图片头。
旧实现只解析第一块，PNG／JPEG／WebP 以 1–2 字节碎片到达或 JPEG 的 SOF
位于较大元数据之后时，会错误报告无法验证尺寸。

新实现仅对需要尺寸校验的 Douyin 图片，在同一个响应内累积最多 1 MiB 的头部。
采用几何解析检查点避免逐字节反复复制／扫描；保留取消与原有 idle budget，
另有不随新片段刷新的 120 秒头部期限。已开始的单次 socket 读取仍受原网络超时控制，
不宣称这是精确到毫秒的硬截止。累积内容原样交还原保存／长度／发布流程，不重编码。
尺寸低于声明值、截断、无法识别或超出预算仍拒绝，不扩展未知格式或放宽媒体验证。

新增 34 项隔离测试覆盖真实 Requests adapter 的碎片行为、三种图片头、较大 JPEG 元数据、
字节完整保留、上限／超时、取消、低尺寸、未知端口拒绝和三次传输重试。
测试的合成图片头用于现有尺寸解析器，不冒充完整图片解码验收。
旧实现的 18 项字节保留负对照为 13 失败、5 通过；修补后同组 18 项全部通过。

### 抖音错误文案误写为小红书

原通用图片尺寸异常固定显示“小红书”，且把解析失败与实测低尺寸混为一谈。
现在使用固定平台映射，未知值安全显示“当前图片”，分开解释无法验证和实测尺寸不足。
不回显原始 URL、签名参数、账号资料，也不在已失败状态下错误保证还会尝试下一条候选。
新增 38 项测试，包括隔离 Chrome 的真实 DOM／事件更新验证。

## 现场验证及仍未解决的部分

第一条指定作品可获得并验证 author-feed 中的 720×1280 候选，实际媒体约 8.67 秒、
861,539 字节；这只证明该档位可用，不证明 default 入口或隐藏更高档位可用。
四条原有 default 官方路由仍失败，包含未验证端口 58001 与 HTTP 403。
端口拒绝的短指纹与用户反馈匹配。额外同作品官方网页入口和桌面浏览器 UA 对照仍失败，
均仅作进程内诊断，没有纳入生产回退策略，也没有保存最终成品。

第二条指定作品匿名与已授权 Profile 均未取得可验证详情，约 120 秒后退出。
现有页面捕获函数固定先访问同作品 `/note/`，仅修改上层 verification URL
不构成独立的 `/video/` 与 `/note/` 页面实验；此前此类尝试不能算两种入口均已实测。
实际 `/video/` 页面导航的单独对照也在约 122 秒后未取得可验证详情。
该对照保留相同的身份校验与总预算，没有进入生产回退策略。第二条尚未进入图片传输阶段，
因此不能将上述确定的分片缺陷声称为这条作品已证实的现场根因。

用户随后确认自己的 Chrome 访问抖音也很慢、页面无法打开。读取已授权 Profile 的 Cookie
已成功，但这不证明网站接受会话；当前没有明确登录／验证码响应，不把它改判成登录失败，
不要求用户发送 Cookie、密码或签名媒体地址。已停止重复请求受阻作品，等待网站可正常访问后
再验证；没有改用其他账号、代理或放宽默认画质校验。
