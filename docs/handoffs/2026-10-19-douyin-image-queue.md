# 抖音图片尺寸失败续队

## 范围

- 基线 `b1a59e01`，分支 `codex/douyin-image-queue`；正式版本 `v0.2.89` / build `100` 已发布。
- 用户补充作者主页与其中失败作品，允许沿用确认过的 Chrome Profile 定向测试该作品。
- 本轮唯一发布者为 Codex；不改已安装 App、系统权限、用户任务历史或其他账号。
- 不合入已暂停的 native 播放内核实验。

## 实站证据

从已确认作者主页定向取得本次新鲜元数据，并通过作品与作者绑定校验。
目标实际是三张图片的图集，不是视频。未下载同主页其他作品。

| 图片 | 网站声明 | 实测 |
| --- | --- | --- |
| 1 | 1000×2079 | 924×1920 |
| 2 | 1000×2079 | 924×1920 |
| 3 | 2079×2079 | 751×751 |

第一张三个原候选镜像均返回相同低尺寸。后续针对每张图对照网站原样返回的
`url_list` 与 `download_url_list` 各一条地址，两类都不足声明尺寸。
正常图片候选带 `tplv-dy-aweme-images:q75` 变换模板；仅记录受控模板与尺寸，
不记录/提交签名 URL、Cookie、原始页面、用户图片或其他账号数据。
不据此断言提高模板质量参数就能拿到原片，也不将下载地址新增为生产回退。
严格生产尺寸门槛拒绝保存，临时测试目录退出后清理，未取得可验收的完整目标图集。

这次错误是可复现的实际尺寸不足，不是 v0.2.87 已修的短图片头问题。
未知 CDN/非标准端口仍阻断，视频 default 最高质量入口仍必须通过。

## 修补

- `downloader.py`：仅所有已尝试候选都具有可解析但不足声明值的尺寸时，抛出独立聚合类型。
  混有其他错误，或此前传输重试已有其他错误时，不允许取得此资格。
  图片外层保留类型；低尺寸文件不落盘、不计成功，声明与实测数字保留。
- `task_manager.py`：native 明确启用的队列按本轮类型证据继续后续作品，再补试一次。
  仅本次执行的局部集合授予资格，不从持久化文本推断；不增加自动后台重跑。
  普通响应变化、登录、验证码、限流、身份与安全门禁仍暂停；standalone 默认不变。
- `static/app.js`：固定格式、合理正整数才显示声明与实测尺寸；恶意附加字段不回显。
- `diagnostic_log.py`：仅增加固定异常名称识别，不输出异常消息、路径或来源地址。
- 已下载文件、目录、任务身份与用户主动继续规则保留；不迁移、删除或重命名用户数据。
